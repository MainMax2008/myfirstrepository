# Правила работы с git

## Коммиты

### Сколько коммитов нужно

Для проекта достаточно **3–5 осмысленных коммитов**. Это значит, что вы
разбиваете работу на **этапы**, и каждый этап — отдельный коммит.

Пример разбиения для любого из трёх проектов:

1. **Инициализация проекта**
   - структура каталогов, система сборки (`CMakeLists.txt`,
     `build.gradle`, `*.csproj`, `pyproject.toml` и т.д.);
   - точка входа, запускается и печатает «Hello».
2. **Игровая логика**
   - правила, состояние игры, валидация ходов.
3. **Пользовательский интерфейс**
   - ввод команд, отрисовка поля, обработка ошибок ввода.
4. **Тесты**
   - юнит-тесты на ключевые правила / сценарии.
5. **Финальная полировка**
   - README проекта, запуск «с нуля», мелкие правки.

### Что писать в сообщении коммита

- Сообщение должно быть **понятно без diff**.
- Плохо: `fix`, `update`, `wip`, `123`, `test`.
- Хорошо:
  - `Инициализация проекта: структура каталогов и CMake`
  - `Реализована проверка правил хода в русских шашках`
  - `Добавлен парсер ввода координат и обработка ошибок`
  - `Покрыты тестами обязательное взятие и превращение в дамку`
  - `README проекта: инструкции по сборке и запуску`

### Чего делать не надо

- Коммитить на каждую добавленную или удалённую функцию.
- Коммитить всё одной кучей `initial commit` в конце.
- Коммитить артефакты сборки, `.venv`, `build/`, `target/` и т.д. — они
  в `.gitignore`.

## Ветки

Достаточно работать в `main`/`master`
