# Итоговый проект курса

В конце курса каждому студенту нужно выполнить **итоговый проект**. На выбор
даётся **три варианта** — нужно выбрать один и реализовать его на удобном
языке: Python, Java, Kotlin, C# или C++

## Как выбрать проект

1. Прочитайте описания в директории [`tasks/`](./tasks):
   - [`tasks/01-checkers.md`](./tasks/01-checkers.md) — Шашки
   - [`tasks/02-battleship.md`](./tasks/02-battleship.md) — Морской бой
   - [`tasks/03-snake.md`](./tasks/03-snake.md) — Змейка
2. Выберите **один**.
3. Настройте проект в директории [`project/`](./project) (там лежит шаблон
   `README.template.md`).
4. Работайте по этапам и делайте коммиты — см.
   [`CONTRIBUTING.md`](./CONTRIBUTING.md) и
   [`docs/git-guidelines.md`](./docs/git-guidelines.md).

## Общие требования ко всем проектам

Оценивается:

- **Оформление и настройка проекта.** Ведение коммитов в git.
- **Удобство использования приложения.**
- **Полнота и корректность реализации приложения.**
- **Стилистическое оформление кода.**
- **README проекта** — как запускать, как играть, все вспомогательные файлы
  (`CMakeLists.txt`, `Makefile`, `build.gradle`, `pom.xml`, `*.csproj` и т.д.).

### Оформление и настройка проекта

- Каждый коммит сопровождается **осмысленным описанием**: что именно
  изменилось и зачем.
- Работа разбивается на **этапы**, каждый этап — коммит. Для проекта
  достаточно **3–5 коммитов**.
- Не нужно дробить на коммит «на каждую функцию» — это тоже плохо.
- Язык описания коммитов — русский или английский, но единообразно.

### Удобство использования

- Приложение будет тестироваться **вручную**. Человек, запустивший его
  впервые, не должен задаваться вопросом «что мне делать?».
- При некорректном вводе приложение не падает: выводится сообщение об
  ошибке и предложение ввести команду снова.
- Если ход нарушает правила — на экран выводится **причина**, почему так
  ходить нельзя.
